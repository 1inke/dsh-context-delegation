# V1.0 Contract: Frozen Architecture Specification

**Product Identity:**
> A context-aware delegation layer for DeepSeek Harness that selects task-relevant persistent project context, supports full and incremental handoffs, delegates work to interchangeable execution backends, independently verifies results, and optionally produces reviewed project-context updates.
>
> 面向 DeepSeek Harness 的上下文智能委派层：负责上下文检索、预算、增量传递、执行器路由、独立验收，以及受审查的长期项目状态更新。

---

## 1. System Dataflow & Responsibilities

The system pipeline strictly separates responsibilities into six linear stages:

```text
Caller / Planner
      │
      ▼
Context Intelligence (Loader -> Chunker -> Query -> Retrieval -> Selection -> Budget -> Delta)
      │
      ▼
Execution Backend (SubagentExecutor / Routed Implementation Provider)
      │
      ▼
Evidence Collection (Independent Git Workspace Evidence + Authorized Verification Runner)
      │
      ▼
Independent Reviewer (Fresh Reviewer Subagent judging Claims vs. Evidence)
      │
      ▼
Context Memory Update (Reviewer-Gated Write-Back: Proposals / Atomic Audited Apply)
```

### Core Invariants
1. **Never Manufacture Success**: If verification commands fail or criteria are unmet, the loop reworks or marks `blocked`.
2. **Read-Only Context by Default**: Write-back operates in `proposal` mode unless explicitly configured as `apply`.
3. **Strict Boundary Confinement**: Workspace root is authoritative; paths outside root or NTFS junctions escaping the workspace trigger `CANONICAL_PATH_ESCAPE`.
4. **Executor Self-Reports are Claims, Not Evidence**: The executor's structured report is treated as an unverified claim until checked against independent git diff and verification execution.

## 3. Subsystem Specifications

### 3.1 Context Engine
- **Deterministic Chunking**: Markdown headings (`#`, `##`, `###`) delineate sections; minimum chunk size 200 chars, maximum chunk size 4,000 chars.
- **Task-Aware Retrieval**: Tokenization strips English/Chinese stopwords; query matches score with heading weighting and path containment bonuses.
- **Budget Allocation**: Hard ceiling `maxContextChars` (default 32k, hard limit 128k). Mandatory files (`agents`, `currentState`, `handoffRules`) have dedicated reserve; remaining budget is distributed across `project`, `decisions`, and `experiments`.
- **Differential Context (V3)**: Handoff computes snapshot SHA-256 fingerprints. When continuing a session, only added, modified, or deleted units are transmitted unless a policy mismatch triggers full refresh.
- **Chunk Caching**: Process-local LRU chunk cache (64 entries) keyed by protocol version, source id, and SHA-256 content hash.

### 3.2 Execution Backends & Routing
- **Executor Interface**:
  ```ts
  export interface DelegationExecutor {
    readonly id: string
    available(): boolean
    execute(request: ExecutorRequest, execution: DelegationExecution): Promise<ExecutorResult>
  }
  ```
- **Operator Routing**: `executorRouting` allows separating `implementation` (e.g. `codex`, `spawn`, `native`) from `reviewer` (e.g. `reviewer-model`). Callers cannot override routing document via tool parameters.

### 3.3 Verification & Review
- **Caller-Authorized Commands**: Only commands in caller-specified `verification_commands` are executed independently. Prohibited commands (privilege escalation, disk formatting, push operations) are rejected as `not-run`.
- **Windows Tree-Kill**: Commands run with an explicit timeout; timeout or cancellation kills the entire process tree (`taskkill /F /T /PID` on Windows, process group kill on POSIX).
- **Reviewer**: Receives caller criteria, independent workspace evidence (git diff), independent verification output, and executor claims. Emits structured `dsh-review-report` (`pass`, `rework`, or `blocked`).
- **Bounded Rework**: Rework loops up to `maxReviewRounds` (default 2), passing accumulated reviewer feedback. Reaching the limit without passing settles as `review-rework-limit-exceeded`.

### 3.4 Context Write-Back
- **Proposal-Only Mode**: Default `proposal` mode records structured patches in the output without modifying files.
- **Apply Mode**: When enabled, valid patches (`CURRENT_STATE.md`, `PROJECT_CONTEXT.md`, `DECISIONS.md`, `EXPERIMENTS.md`) are atomically written and the context snapshot revision advances.

### 3.5 Observability
- Process-local ring buffer holds 20 recent traces recording stage timestamps, loaded file counts, context character counts, execution times, and outcomes.
- Traces omit sensitive executor output, verification outputs, or reasoning texts.
- Accessible via `delegation_debug` tool.

## 4. Package & Public Interface Stability

The package maintains zero breaking changes to external consumers:
- Package exports:
  - `.` -> `./lib/index.js`
  - `./tool` -> `./lib/tool.js`
  - `./preview` -> `./lib/preview.js`
- Cordis service: `ctx.codexContextDelegation`
- Model-facing tools: `codex_expert`, `context_preview`, `delegation_debug`
- Engines: `^22.19.0 || >=24.0.0`
